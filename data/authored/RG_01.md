subtopic: Maximum spanning tree preserves all bottleneck paths
time: $O(E\log E+V^2)$ overall
space: $O(E+V)$ excluding the output
complexity_note: Auxiliary space excludes the buffered input and output.
---
Build a maximum spanning tree using descending-weight Kruskal. For any pair of vertices, the minimum-weight edge on their tree path equals the largest achievable path bottleneck in the original graph. If a better bottleneck existed, it would cross the cut of that minimum tree edge with a heavier edge, contradicting maximum spanning-tree optimality.

Traverse the tree once from each start vertex, carrying the minimum weight seen so far. Output those bottlenecks as a row, with zero on the diagonal. This takes quadratic traversal time, matching the number of output entries.

## Edge cases

- Vertices are zero-based.
- Zero-weight edges are valid.
- The diagonal is explicitly zero.
- Output rows incrementally to avoid storing the entire matrix.

## Dry run

The sample maximum spanning tree uses edges `0-2` of weight three and `1-2` of weight two. The path from 0 to 1 has minimum edge two, improving on their direct edge of weight one.

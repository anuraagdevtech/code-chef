## Question

**Problem Statement**

**Past**

In the year of 2048, the Virtual Reality Massively Multiplayer Online Role-Playing Game (VRMMORPG), **Code Art Online (CAO)**, is released. With the Chef Gear, a virtual reality helmet that stimulates the user's five senses via their brain, players can experience and control their in-game characters with their minds.

On August the 2nd, 2048, all the players log in for the first time, and subsequently discover that they are unable to log out. They are then informed by Code Master, the creator of CAO, that if they wish to be free, they must reach the second stage of the game.

Kirito is a known star player of CAO. You have to help him log out.

**Present**

*Stage 1*

A map is described by a 2D grid of cells. Each cell is either labelled as a **#** or a **^**. **#** denotes a wall. A monster exists in a cell if the cell is not a wall and the cell is a **centre of Prime-Cross (CPC)**.

- Let **L** be the number of contiguous **^** to the left of **X**, in the same row as **X**.

- **R** be the number of contiguous **^** to the right of **X**, in the same row as **X**.

- **T** be the number of contiguous **^** above **X**, in the same column as **X**.

- **B** be the number of contiguous **^** below **X**, in the same column as **X**.

A cell **X** is said to be a **CPC** if there exists a prime number **P** such that **P ≤ minimum of [L, R, T, B]**.

**Note:** While computing **L, R, T, B** for a cell **X**, you should not count the **^** of the cell **X**.

Given a map, you have to tell Kirito the number of cells where monsters exist.

**Future**

If you are done with this task, go help Kirito with Stage 2 :-)

**Input**

The first line of the input contains an integer **T** denoting the number of test cases. The description of **T** test cases follows. Each case starts with a line containing two space separated integers **R, C** denoting the number of rows and columns in the map respectively. The next **R** lines contain **C** characters each, describing the map.

**Output**

For each test case, output a single line containing the number of cells where monsters exist.

**Constraints**

- 1 ≤ **T** ≤ 100

- 1 ≤ **R** ≤ 50

- 1 ≤ **C** ≤ 50

## Constraints

- 1 ≤ T ≤ 100
- 1 ≤ R ≤ 50
- 1 ≤ C ≤ 50

**Example case 1.** There is no cell for which minimum of L, R, T, B is greater than some prime P.

## Approach

A cell is a *centre of Prime-Cross* when some prime $P$ satisfies $P \leq \min(L, R, T, B)$. Since the **smallest prime is $2$**, such a $P$ exists exactly when

$$\min(L, R, T, B) \geq 2$$

That reduction is the whole trick — no primality testing is needed, and the word "prime" in the statement is a misdirection.

So compute, for every cell, how many contiguous `^` lie immediately to its left, right, above and below (not counting the cell itself), and count the cells whose smallest of the four reaches $2$.

All four tables come from running prefix scans, each in $O(RC)$:

- sweeping each row left to right gives $L$;
- right to left gives $R$;
- each column top to bottom gives $T$;
- bottom to top gives $B$.

In each case the recurrence is "previous run $+ 1$ if the neighbour is `^`, else $0$". Computing the runs by walking outward from every cell instead would be $O(RC \cdot \max(R,C))$ — fine at $50 \times 50$, but the prefix version is the habit worth keeping.

Sample case 1 is instructive: in a $5\times5$ grid only the very centre has room for two cells on every side, and the single `#` at row $2$ sits in its row, cutting $R$ to $1$. So the answer is $0$ despite the grid being almost entirely open.

Wall cells are never centres, and their run values are $0$ by construction, so no separate guard is needed beyond skipping them.

## Solution

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        rows, cols = int(data[pos]), int(data[pos + 1])
        grid = [data[pos + 2 + i].decode() for i in range(rows)]
        pos += 2 + rows
        open_ = [[c == "^" for c in row] for row in grid]
        left = [[0] * cols for _ in range(rows)]
        right = [[0] * cols for _ in range(rows)]
        top = [[0] * cols for _ in range(rows)]
        bottom = [[0] * cols for _ in range(rows)]
        # Each run is the neighbour's run plus one, or zero at a wall.
        for r in range(rows):
            for c in range(1, cols):
                left[r][c] = left[r][c - 1] + 1 if open_[r][c - 1] else 0
            for c in range(cols - 2, -1, -1):
                right[r][c] = right[r][c + 1] + 1 if open_[r][c + 1] else 0
        for c in range(cols):
            for r in range(1, rows):
                top[r][c] = top[r - 1][c] + 1 if open_[r - 1][c] else 0
            for r in range(rows - 2, -1, -1):
                bottom[r][c] = bottom[r + 1][c] + 1 if open_[r + 1][c] else 0
        # The smallest prime is 2, so "some prime <= min" means min >= 2.
        count = sum(1 for r in range(rows) for c in range(cols)
                    if open_[r][c]
                    and min(left[r][c], right[r][c], top[r][c], bottom[r][c]) >= 2)
        out.append(str(count))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## Edge cases

- **"Some prime $P \leq \min$" is just $\min \geq 2$**, because $2$ is the smallest prime — so no primality testing is needed at all.
- **The cell itself is excluded from every arm**, as the statement's note insists; the recurrence encodes that by reading the *neighbour's* arm and adding one only when that neighbour is open.
- **A wall truncates the arm to zero at that point**, which is what the reset in the recurrence does — and it is why the first sample answers $0$: the lone `#` leaves the centre cell with a right-arm of only $1$.
- **A cell within one step of any border fails on that arm**, so the outer two rings of the grid never contribute and need no special-casing.
- **The cell must itself be open**; a wall is never a monster's home however long its arms would be.
- **Four separate passes** build the arms — two row sweeps in opposite directions and two column sweeps — because each direction needs the neighbour already computed.
- **$R, C \leq 50$** with $T \leq 100$, so the five grids per case are cheap.

## Dry run

First sample: a $5 \times 5$ grid of `^` with a single `#` at row $3$, column $5$.

Only the centre cell $(3,3)$ is far enough from every border to have a chance:

| direction | contiguous `^` (excluding the cell) |
|---|---:|
| left | 2 |
| right | 1 — blocked by the `#` at column $5$ |
| top | 2 |
| bottom | 2 |

$\min = 1 < 2$, so it is not a CPC and the answer is `0`.

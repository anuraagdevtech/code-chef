# 366. Stamps 100

> [`S100`](https://www.codechef.com/problems/S100) &middot; difficulty **1631** &middot; time limit **1s** &middot; 1600 to 1800 difficulty problems (Level 3)

## Topic used

| | |
|---|---|
| **Topic** | Greedy |
| **Technique** | A right-to-left cascade zeroes everything after one position |
| **CodeChef tags** | `Data Structures`, `String` |
| **Complexity class** | Linear $O(n)$ |
| **Time** | $O(N)$ per test case |
| **Space** | $O(N)$ |

## Question

You are given a **binary** string $S$ of length $N$.

You can apply the following operation any (possibly zero) number of times:
- Select an integer $i\ \lparen 1 \leq i \leq N-2 \rparen$ and replace the substring $S_i S_{i+1} S_{i+2}$ with `100`.

Find the **lexicographically smallest** string after the operations.

Note: String $X$ is lexicographically smaller than string $Y$ if $X_i \lt Y_i$, where $i$ is the first index where $X$ and $Y$ differ.

**Input**

- The first line of input will contain a single integer $T$, denoting the number of test cases.
- Each test case consists of multiple lines of input.
    - The first line of each test case contains an integer $N$ — the length of string $S$.
    - The second line of each test case contains a binary string $S$.

**Output**

For each test case, output the **lexicographically smallest** string after the operations.

## Constraints

- $1 \leq T \leq 10^5$
- $3 \leq N \leq 3 \cdot 10^5$
- $|S| = N$
- Each character of $S$ is either `0` or `1`.
- The sum of $N$ over all test cases won't exceed $3 \cdot 10^5$.

**Subtasks**

- **Subtask 1 (10 points):** $1 \leq M \leq 10$
- **Subtask 2 (20 points):** The sum of $N$ across all test cases won't exceed $20$.
- **Subtask 3 (70 points):** No further constraints.

## Sample

**Sample input**

```
2
3
110
4
0001
```

**Sample output**

```
100
0001
```

<details><summary>Explanation</summary>

**Test case $1$:** You can convert $S$ into `100`.
Since `100` is lexicographically smaller than `110`, output `100`.

**Test case $2$:** You should keep $S$ as it is without applying any operations, so output `0001`.

</details>

## Approach

The operation writes `100` over a window, so it **plants a one** at the window's start. Any operation applied at a position currently holding `0` therefore raises that character and makes the string lexicographically larger, so only positions already holding `1` are worth touching — and the leading zeros are untouchable.

The real leverage comes from applying operations **right to left**. Running them at $N-3, N-4, \ldots, p$ in that order, each window's `100` overwrites the previous window's leading one, so the zero region grows leftwards and the result is

$$S_1 \ldots S_{p-1} \,\|\, 1 \,\|\, \underbrace{0 \cdots 0}_{N-p}$$

for any $p \leq N-3$. Among these, the smallest $p$ with $S_p = 1$ wins: all candidates agree on the prefix, and a larger $p$ keeps $S$'s own characters — including a `1` at that later position — where the smaller $p$ has already zeroed everything.

Position $p$ itself cannot be lowered, since turning it into a `0` requires an operation at $p-1$ or $p-2$, which would raise an earlier character. So with $f$ the index of the first `1`:

$$\text{answer} = \begin{cases} 0^{f}\,1\,0^{\,N-f-1} & f \leq N-3 \\ S & \text{otherwise} \end{cases}$$

The second branch covers a first `1` in the last two positions (and an all-zero string): no legal window starts there, and any window that would reach it starts on a `0`.

The samples are one of each. `110` has $f = 0 \leq N-3 = 0$, giving `100`. `0001` has $f = 3 > 1$, so it is already optimal — note `0100`, from operating at index $1$, is strictly worse.

The cascade is what makes the greedy non-obvious: on `1111` the left-to-right instinct gives `1001`, while going right to left reaches `1000`.

## Solution

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    out = []
    for i in range(t):
        n = int(data[1 + 2 * i])
        s = data[2 + 2 * i]
        first = s.find(b"1")
        # A right-to-left cascade from the first one zeroes the whole tail.
        if 0 <= first <= n - 3:
            out.append("0" * first + "1" + "0" * (n - first - 1))
        else:
            out.append(s.decode())
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## Edge cases

- **The operation can only *write* a `1` at position $i$**, so applying it anywhere before the first existing `1` makes the string lexicographically larger. The leading zeros are therefore untouchable, and the first `1` cannot move left.
- **A right-to-left cascade zeroes the whole tail.** Applying at $N-2$, then $N-3$, and so on down to the first `1` leaves exactly one `1` — at that first position — with zeros everywhere after it, which is the smallest reachable string.
- **The cascade needs room.** It only starts if the first `1` is at index $N-3$ or earlier (0-based), i.e. there is a legal $i \geq \text{first}$; otherwise no operation can touch those trailing ones without introducing an earlier `1`.
- **So a `1` in the last two positions is frozen** — the second sample, `0001`, comes back unchanged.
- **An all-zero string** has no `1` at all and is already minimal, which the `0 <= first` guard covers.
- **The operation window is three characters**, so $N \geq 3$ is required, and the constraints guarantee it.
- **Sum of $N \leq 3 \cdot 10^5$**: one `find` and one string build per case.

## Dry run

First sample: $N = 3$, $S = $ `110`. The first `1` is at index $0 \leq N - 3 = 0$, so the cascade applies.

| step | string |
|---|---|
| start | `110` |
| apply at $i = 0$ | `100` |

Output `100`. For a longer example, `111111` cascades from the right: `111100`, `111000`, `110000`, `100000`.

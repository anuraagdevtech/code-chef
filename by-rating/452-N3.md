# 452. K-important Strings

> [`N3`](https://www.codechef.com/problems/N3) &middot; difficulty **1729** &middot; time limit **0.5s** &middot; Rise from 3* to 4* (Level 4)

## Topic used

| | |
|---|---|
| **Topic** | Strings |
| **Technique** | Pairwise overlaps by KMP, then a shortest walk with exactly K vertices |
| **Complexity class** | Cubic or higher polynomial $O(n^3)$ and above |
| **Time** | $O(N^2 L + K N^2)$ per test case |
| **Space** | $O(N^2 + K N + K L)$ |

## Question

You are given a set of N strings S_0, S_1, …, S_N-1. These strings consist of only lower case characters a..z and have the same length L.

A string H is said to be K-important if there are at least K strings in the given set of N strings appearing at K different positions in H. These K strings need not to be distinct.

Your task is to find the shortest K-important string. If there are more than one possible solution, your program can output any of them.

**Input**

The first line contains a number t (about 10) which is the number of test cases.

Each test case has the following form.

The first line contains three integers N, L and K. The next N lines contain the strings in the given set.

Each test case's input is separated by a blank line.

**Constraints**

- 1 ≤ N ≤ 150

- 1 ≤ L ≤ 300

- 1 ≤ K ≤ 500

**Output**

For each test case, output the following information.
The first line contains the length of the shortest K-important strings.

The second line contains H, one of the K-important strings.

Each line in the next K lines contains the index of one string in the given set that appears in H and the corresponding position (0-based) in H.

Print a blank line after each test case's output.

## Constraints

- 1 ≤ N ≤ 150
- 1 ≤ L ≤ 300
- 1 ≤ K ≤ 500

## Approach

All strings have the same length $L$, so no string can sit strictly inside another: in a shortest answer the $K$ occurrences are ordered by position and each consecutive pair overlaps as much as possible. If string $j$ follows string $i$, the new characters needed are $L - \text{ov}(i, j)$, where $\text{ov}(i, j)$ is the longest suffix of $S_i$ that is a prefix of $S_j$ and is shorter than $L$ (the positions must differ, so a full overlap is not allowed).

Compute every $\text{ov}(i, j)$ by running the KMP automaton of $S_j$ over $S_i$ without its first character. Then the task is a cheapest walk on $K$ vertices in a complete directed graph with edge weight $L - \text{ov}(i, j)$: a DP over the number of strings placed, `cost[j]` being the shortest text that ends with $S_j$, with a parent table per layer for reconstruction.

Rebuild the walk backwards, then glue the strings together, recording each start position.

## Solution

```python
import sys
from array import array


def main() -> None:
    tokens = iter(sys.stdin.buffer.read().split())
    out = []
    for _ in range(int(next(tokens))):
        n, length, k = (int(next(tokens)) for _ in range(3))
        strings = [next(tokens).decode() for _ in range(n)]
        overlap = [[0] * n for _ in range(n)]
        for j in range(n):
            pattern = strings[j]
            failure = [0] * length
            for p in range(1, length):
                v = failure[p - 1]
                while v and pattern[p] != pattern[v]:
                    v = failure[v - 1]
                failure[p] = v + (pattern[p] == pattern[v])
            for i in range(n):
                matched = 0
                for ch in strings[i][1:]:
                    while matched and ch != pattern[matched]:
                        matched = failure[matched - 1]
                    if ch == pattern[matched]:
                        matched += 1
                overlap[i][j] = matched
        cost = [length] * n
        parents = []
        for _ in range(k - 1):
            next_cost = [10 ** 9] * n
            prev = array('h', [-1]) * n
            for i in range(n):
                base = cost[i] + length
                for j in range(n):
                    v = base - overlap[i][j]
                    if v < next_cost[j]:
                        next_cost[j] = v
                        prev[j] = i
            parents.append(prev)
            cost = next_cost
        last = min(range(n), key=cost.__getitem__)
        path = [last]
        for prev in reversed(parents):
            last = prev[last]
            path.append(last)
        path.reverse()
        answer = strings[path[0]]
        positions = [0]
        for i, j in zip(path, path[1:]):
            positions.append(len(answer) - overlap[i][j])
            answer += strings[j][overlap[i][j]:]
        out.extend((str(len(answer)), answer))
        out.extend((f'{i} {p}' for i, p in zip(path, positions)))
        out.append('')
    print('\n'.join(out))


if __name__ == "__main__":
    main()
```

## Edge cases

- The same string may be used several times; its overlap with itself is its longest proper border.
- $K = 1$: the answer is any single string at position 0.
- Any shortest answer is accepted, so ties in the DP can be broken arbitrarily.
- Test cases are separated by blank lines, which token-based reading skips for free.

## Dry run

Strings `abc`, `cde`, `bcf`, $K = 2$.

Useful overlaps: `abc -> bcf` is 2 (`bc`), `abc -> cde` is 1 (`c`), everything else is 0. The cheapest two-vertex walk is `abc -> bcf` with cost $3 + 3 - 2 = 4$.

Output: length 4, the text `abcf`, then `0 0` (string 0 at position 0) and `2 1` (string 2 at position 1).

# 296. The One On The Last Night

> CodeChef problem code [`S06E06`](https://www.codechef.com/problems/S06E06) &middot; difficulty **1596** &middot; time limit **0.5s**

| | |
|---|---|
| **Topic** | Greedy |
| **Technique** | Raise the smallest digit first |
| **Time** | $O(d \log d)$ per test case with $d \leq 7$ digits |
| **Space** | $O(d)$ |
| **Roadmap course** | 1400 to 1600 difficulty problems (Level 2) |

## Question

*Chandler wants to give Joey money as Joey is going through some financial struggles. He believes $1500 will be enough to pay off the bills. Chandler makes up a game on the spot called "Cups", which has no rules. Every move Joey makes in the "game", Chandler says that he wins a lot of money. Joey, being "smart", finds this out and thus wants to set some rules.*

Joey and Chandler have a set of cards, where the **value** of a card is defined as the product of all the digits of the number printed on that card.

For example, value of the card with the number $7$ equals $7$, value of the card with the number $203$ equals $2 \cdot 0 \cdot 3 = 0$.

The initial number on Joey's card is $N$ (without any leading zeroes). Chandler can make at most $K$ changes on the digits of the number before it gets noticed. In one change, he can choose any digit $x$ ($x ≠ 9$) of the number printed on card and replace it with $x+1$.
Find the maximum possible value of Joey's card after making the changes.

**Input**

- First line will contain $T$, number of testcases. Then the testcases follow.
- For each test case, given two integer $N$ and $K$, denoting the initial number on Joey's card and the number of changes Chandler can make.

**Output**

For each testcase, output in a single line the maximum possible value of Joey's card after making the changes.

## Constraints

- $1 \leq T \leq 10^3$
- $1 \leq N \leq 10^6$
- $0 \leq K \leq 10^6$

## Sample

**Sample input**

```
3
1 5
2221 3
123456 0
```

**Sample output**

```
6
36
720
```

<details><summary>Explanation</summary>

**Test case 1**: Chandler can increase the digit $1$ five times to make the final number on card $6$.

**Test case 2**: Chandler can increase the first digit of the given number once and the last digit twice. After making these changes, the final number on the card would be $3223$, whose value is equal to $36$. There are other ways to make changes on the printed number which may lead to one of the following numbers being the resulting number on card : $2233$, $2323$, $2332$, $3232$, $3322$; note that all these numbers have their values equal to $36$ as well.

</details>

## Approach

Raising a digit from $x$ to $x+1$ multiplies the product by $\frac{x+1}{x}$ — a ratio that **shrinks as $x$ grows**: $1 \to 2$ doubles, $2 \to 3$ gives $1.5$, $8 \to 9$ gives only $1.125$. So each increment is best spent on the **smallest** digit available.

A digit of $0$ is the extreme case: the product is zero until every $0$ is lifted, and since $0$ is also the smallest digit, the greedy handles it without a special rule.

The bound that makes this trivial to execute: $N \leq 10^6$ has at most $7$ digits, so the total number of useful increments is at most $7 \times 9 = 63$. Any $K$ beyond that leaves every digit at $9$. So the loop runs $\min(K, 63)$ times regardless of $K$ reaching $10^6$ — no need to reason about huge budgets.

A min-heap keeps "smallest non-nine digit" cheap, though with seven digits a plain scan would do.

Sample case 2, $N = 2221$ with $K = 3$: the $1$ is raised to $2$, then two of the $2$s become $3$s, giving digits $\{2,2,3,3\}$ and a product of $36$. Spending all three on one digit instead would give $\{2,2,2,4\}$ and only $32$ — spreading across the smallest digits wins.

Sample case 1 raises a lone $1$ five times to $6$. Sample case 3 has $K = 0$ and simply multiplies $1 \times 2 \times \cdots \times 6 = 720$.

## Solution (Python)

```python
import heapq
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    out = []
    for i in range(t):
        digits = [c - 48 for c in data[1 + 2 * i]]
        k = int(data[2 + 2 * i])
        heapq.heapify(digits)
        # At most 7 digits x 9 steps, so a huge K just saturates everything.
        while k and digits[0] < 9:
            heapq.heapreplace(digits, digits[0] + 1)
            k -= 1
        product = 1
        for d in digits:
            product *= d
        out.append(str(product))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## Complexity

- **Time:** $O(d \log d)$ per test case with $d \leq 7$ digits
- **Space:** $O(d)$

## Edge cases

- **Raising the smallest digit first is optimal**, because incrementing $d$ scales the product by $(d+1)/d$, which is largest when $d$ is smallest — so a min-heap drives the greedy with no lookahead.
- **A zero digit is the extreme case of that rule.** The product is $0$ while any digit is $0$, and lifting it to $1$ is worth more than any other increment, which the heap does automatically by putting $0$ first.
- **Digits cap at $9$**, so the loop must stop when the smallest digit is already $9$ — otherwise a large $K$ would spin forever. With at most seven digits, $63$ increments saturate everything.
- **$K$ may be enormous** relative to the digits ($K \leq 10^6$ against $N \leq 10^6$), so the saturation guard is doing real work, not just tidying up.
- **$K = 0$** leaves the number alone and the answer is the plain digit product (the third row, $1 \cdot 2 \cdots 6 = 720$).
- **Leading zeros are absent from the input**, and the greedy never creates one since it only increases digits.
- **The digits come straight from the byte token** with `c - 48`, avoiding a decode per case.

## Dry run

Second sample: $N = 2221$, $K = 3$.

| step | digits (as a multiset) | product |
|---:|---|---:|
| start | $1, 2, 2, 2$ | 8 |
| raise the $1$ | $2, 2, 2, 2$ | 16 |
| raise a $2$ | $2, 2, 2, 3$ | 24 |
| raise a $2$ | $2, 2, 3, 3$ | **36** |

Output `36`. Spending all three on one digit instead ($1 \to 4$) would give $4 \cdot 2 \cdot 2 \cdot 2 = 32$.

## Question

Vasya likes the number $239$. Therefore, he considers a number *pretty* if its last digit is $2$, $3$ or $9$.

Vasya wants to watch the numbers between $L$ and $R$ (both inclusive), so he asked you to determine how many pretty numbers are in this range. Can you help him?

**Input**
- The first line of the input contains a single integer $T$ denoting the number of test cases. The description of $T$ test cases follows.
- The first and only line of each test case contains two space-separated integers $L$ and $R$.

**Output**
For each test case, print a single line containing one integer — the number of pretty numbers between $L$ and $R$.

**Constraints**
- $1 \le T \le 100$
- $1 \le L \le R \le 10^5$

**Subtasks**
**Subtask #1 (100 points):** original constraints

## Approach

A number is *pretty* when its last digit is $2$, $3$ or $9$ — that is, when $n \bmod 10 \in \{2, 3, 9\}$. The task is to count them in $[L, R]$.

The standard move for a range count is to define a prefix function $f(n)$ = how many pretty numbers lie in $[1, n]$, and answer

$$f(R) - f(L - 1)$$

Subtracting the prefix below $L$ is what makes the range inclusive at both ends without any boundary fiddling.

For $f$, count each qualifying last digit separately. The numbers $\leq n$ ending in digit $d$ are $d, d+10, d+20, \ldots$, of which there are

$$\left\lfloor \frac{n - d}{10} \right\rfloor + 1 \quad \text{when } n \geq d, \text{ else } 0$$

Summing over $d \in \{2, 3, 9\}$ gives $f(n)$ in constant time.

A brute-force loop over $[L, R]$ is the obvious alternative, and at $R \leq 10^5$ with $T \leq 100$ that is up to $10^7$ iterations — fast in C, genuinely slow in Python, and the kind of thing that turns a correct solution into a timeout. The closed form sidesteps it. A precomputed prefix-sum array over $[0, 10^5]$ would also work and is what the problem's tags suggest, trading $O(10^5)$ memory for the same $O(1)$ queries.

Checking sample 2: in $[11, 33]$ the pretty numbers are $12, 13, 19, 22, 23, 29, 32, 33$ — eight of them.

## Solution (Python)

```python
import sys

PRETTY = (2, 3, 9)


def upto(n: int) -> int:
    """How many pretty numbers lie in [1, n]."""
    if n <= 0:
        return 0
    return sum((n - d) // 10 + 1 for d in PRETTY if n >= d)


def main() -> None:
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    out = []
    for i in range(t):
        l, r = int(data[1 + 2 * i]), int(data[2 + 2 * i])
        # Inclusive range count via prefix subtraction.
        out.append(str(upto(r) - upto(l - 1)))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## Complexity

- **Time:** $O(1)$ per test case
- **Space:** $O(1)$

## Edge cases

- **$L = 1$**: the prefix count must be evaluated at $0$, so the `n <= 0` guard matters — without it the arithmetic would produce a negative contribution.
- **$n$ smaller than one of the digits** ($n = 1$ against the digit $2$): the `n >= d` filter stops that term from counting a number that does not exist yet.
- **A range inside a single decade** ($11$ to $13$ gives $12, 13$, so $2$): the prefix difference handles it without any special case.
- **Both ends inclusive**: using $\mathrm{upto}(R) - \mathrm{upto}(L-1)$ rather than $\mathrm{upto}(L)$ is what keeps $L$ itself in the count.
- Three of every ten numbers are pretty, so the answer is always close to $0.3(R - L + 1)$ — a useful sanity check.

## Dry run

Second sample, $L = 11$ to $R = 33$:

| last digit | counted in $[1,33]$ | counted in $[1,10]$ | difference |
|---:|---|---|---:|
| 2 | $2, 12, 22, 32$ | $2$ | 3 |
| 3 | $3, 13, 23, 33$ | $3$ | 3 |
| 9 | $9, 19, 29$ | $9$ | 2 |

Totals $11 - 3 = 8$, so the output is `8`. The first sample is $\mathrm{upto}(10) - \mathrm{upto}(0) = 3 - 0 = 3$.
